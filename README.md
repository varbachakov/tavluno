# Tavluno — правила сдачи работ

Работаем через **личный форк**. Каждое задание сдаём через **Pull Request (PR)** в [общий репозиторий](https://github.com/varbachakov/tavluno).

## Один раз перед началом

1. Нажмите **Fork** справа вверху страницы общего репозитория. В поле **Owner** выберите свой аккаунт и нажмите **Create fork**.

   ![Кнопка Fork в правом верхнем углу страницы репозитория на GitHub](https://docs.github.com/assets/cb-34352/images/help/repository/fork-button.png)

   Кнопка Fork на примере из [документации GitHub](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/fork-a-repo).

2. Клонируйте **свой форк** на компьютер и откройте проект в редакторе.

## Для каждого задания

1. На GitHub откройте **свой форк**, на вкладке **Code** выберите `main`. Над списком файлов нажмите **Sync fork → Update branch**.

   ![Кнопка Sync fork над списком файлов своего форка на GitHub](https://docs.github.com/assets/cb-75605/images/help/repository/sync-fork-dropdown.png)

   Скриншот из [документации GitHub](https://docs.github.com/en/pull-requests/how-tos/work-with-forks/syncing-a-fork).

   Затем в терминале в папке проекта выполните `git switch main` и `git pull --ff-only origin main`, чтобы обновить проект на компьютере.

2. Создайте ветку от обновлённой `main`: например, `tumanov/lesson-01`. Подставляйте свою фамилию и номер задания.
3. Выполните задание **только в своей папке**. Проверьте страницу в браузере.
4. Сделайте **commit** и **push** рабочей ветки в свой форк.
5. Откройте **Pull Request** из этой ветки в общий репозиторий.

## Куда направлять PR

В GitHub откройте **New pull request → compare across forks** и проверьте:

| Поле | Значение |
|---|---|
| **base repository** | `varbachakov/tavluno` |
| **base** | `main` |
| **head repository** | Ваш форк |
| **compare** | Ветка задания, например `tumanov/lesson-01` |

**Название:** `Туманов — занятие 01: HTML-разметка`.

**Описание:** что сделано, скриншот результата и вопросы, если они есть.

Перед отправкой проверьте **Files changed**: в PR должны быть только изменения вашей работы.

## После проверки

- Если есть замечания, исправьте их **в той же ветке**, сделайте commit и push. PR обновится автоматически.
- Работу принимает и сливает преподаватель. Дождитесь статуса **Merged**.
- Следующее задание начинайте в новой ветке от обновлённой `main`.

**Правила:** не выполняйте задания в `main`; не меняйте чужие папки и общие файлы; один PR — одно задание. Если Git сообщает об ошибке или конфликте, обратитесь к преподавателю.
